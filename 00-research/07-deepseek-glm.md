# DeepSeek V4.1 Flash и GLM-5.3-Flash: как с ними работать агенту

Обе модели — публичные, с открытыми весами под MIT, обе «думающие» (reasoning) и обе принимают изображения.
Ниже — факты из официальных источников, затем практические правила для вашего набора.
Пометка **(вывод)** — моя рекомендация, а не утверждение источника.

## Паспорт моделей
| | DeepSeek V4.1 Flash | GLM-5.3-Flash |
|---|---|---|
| Разработчик, дата | DeepSeek, 10.09.2026 | Z.ai (Zhipu), 2026 |
| Архитектура | MoE, 552B (активно ~8B на входе, 16B на генерации) | MoE, 320B (18B активно) |
| Контекст | 1M токенов | 1M токенов |
| Изображения | да, встроенное зрение | да, первая нативно мультимодальная в GLM-5 |
| Инструменты (tool calling) | да, только `function` | да, OpenAI-схема |
| Рассуждение | включено по умолчанию, можно выключить | **всегда включено**, можно только уменьшить |
| Рекомендуемые семплы | temperature 1.0, top_p 0.95 | temperature 1.0, top_p 0.95 (менять только одно) |
| Позиционирование | дешёвый уровень V4.1; кодовые, терминальные агенты | Flash — вызовы функций и массовые запросы; полная GLM-5.3 — глубокие кодовые агенты |

## DeepSeek V4.1 Flash: что важно знать
- **Рассуждение**: `reasoning_effort` = `none | low | high | max` (по умолчанию `high`; `none` выключает). В API DeepSeek имя модели — `deepseek-flash`.
- **Temperature в режиме рассуждения игнорируется**; `top_p` ниже 0.95 поднимается до 0.95.
- **`tool_choice: "required"` и принудительный вызов конкретного инструмента в режиме рассуждения не поддерживаются** — сервер вернёт ошибку 400.
- **`max_tokens`**: рассуждение и ответ делят один бюджет (по умолчанию 64K в режиме рассуждения, 128K на `max`). Маленький лимит → пустой ответ с `finish_reason=length`.
- **JSON-режим** (`response_format: json_object`) требует явно попросить JSON в промпте, иначе модель может «стримить пробелы» до лимита.
- **Развёртывание в vLLM** (0.30.0+, пока только Docker-образ nightly): нужны флаги `--tokenizer-mode deepseek_v41 --tool-call-parser deepseek_v41 --enable-auto-tool-choice --reasoning-parser deepseek_v41`. Флаг `--language-model-only` **отключает зрение** — скриншоты работать не будут. Веса ~476 GiB, помещается на один узел 8×H200.
- **Шкала усилия различается**: в API DeepSeek `low/high/max` = 50/75/100, во vLLM `low/high/xhigh/max` = 25/50/75/100 (по умолчанию 50). Нужна одинаковость — передавайте число 1–100.
- **Обвязка агента**: в собственных тестах DeepSeek на Terminal-Bench 2.1 их агент в режиме Minimal набрал 90.6 против 85.8 в режиме Standard. **(вывод)** Короткие инструкции и минимум лишних инструментов этой модели идут на пользу — ещё один довод держать `AGENTS.md` коротким.

## GLM-5.3-Flash: что важно знать
- **Рассуждение всегда включено**; `reasoning_effort` = `low | high | max` (по умолчанию `max`). Любое другое значение молча превращается в `max` — проверяйте строку в конфиге.
- Уровни грубые и не строго монотонные: замеряйте расход токенов на своих задачах.
- **Сохранение рассуждений между шагами** (`clear_thinking: false`) улучшает связность агентной работы и попадания в кэш, **но только если клиент возвращает `reasoning_content` дословно**. Если клиент этого не делает — ставьте `clear_thinking: true` (карточка модели советует это для обычного чата).
- **Советы по промптам от провайдера**: ставьте цель высокого уровня — модель сама разобьёт задачу; **жёсткие ограничения пишите явно** («без новых зависимостей», «не менять API», «запусти тесты»); подбирайте `reasoning_effort` под сложность: `low` — простые шаги, `max` — планирование.
- **Развёртывание в vLLM** (0.29.0+): `--tool-call-parser glm47 --reasoning-parser glm47 --enable-auto-tool-choice`; FP8-веса ~306 GiB; на Hopper KV-кэш только BF16.
- Структурированный вывод: `response_format` с `json_schema`; разбирать только `content`, не `reasoning_content`.

## Подключение в Qwen Code (и любой OpenAI-совместимый клиент)
- **Для внутреннего сервера (vLLM) уровень рассуждения задавайте через `extra_body.reasoning_effort`.** Причины из документации Qwen Code: настройка `generationConfig.reasoning` для OpenAI-совместимых провайдеров игнорируется, если задан `samplingParams`; а для неизвестных хостов клиент шлёт вложенный объект `reasoning`, который vLLM не поймёт. `extra_body` уходит в запрос как есть.
- Пример для обеих моделей — `02-agent-kit/.qwen/settings.example.json`. `id` должен совпадать с `--served-model-name` на сервере.
- **Не ставьте temperature 0–0.1.** Для DeepSeek в режиме рассуждения она игнорируется, для GLM рекомендована 1.0. **(вывод)** Предсказуемость обеспечивают шаблоны, проверки и скрипты, а не низкая температура.
- **`max_tokens` ≥ 32–64K** для обеих, иначе рассуждение съест бюджет и ответ будет пустым.
- **Окно контекста**: модели умеют 1M, но сервер часто ограничен `--max-model-len`. В `contextWindowSize` пишите то, что реально отдаёт ваш сервер.

## Признаки того, что сервер настроен неправильно
| Симптом | Вероятная причина |
|---|---|
| Модель пишет вызов инструмента текстом (`<tool_call>`, DSML-теги) вместо вызова | на сервере не включены `--tool-call-parser` / `--enable-auto-tool-choice` |
| В ответе видны рассуждения вперемешку с кодом | не включён `--reasoning-parser` |
| Пустой ответ, `finish_reason=length` | мал `max_tokens`, рассуждение съело бюджет |
| Ошибка 400 при вызове инструментов у DeepSeek | `tool_choice: required` в режиме рассуждения |
| Модель «не видит» скриншот | сервер запущен без зрения (`--language-model-only` у DeepSeek) |
| Агент теряет нить после нескольких шагов (GLM) | `clear_thinking: false`, а клиент не возвращает рассуждения → поставить `true` |

## Как распределить работу между двумя моделями **(вывод — проверить на контрольных задачах)**
| Задача | Модель | `reasoning_effort` |
|---|---|---|
| Ручные кейсы по документации и скриншотам | GLM-5.3-Flash | high |
| Автотест по кейсу (код, компиляция, запуск) | DeepSeek V4.1 Flash | high |
| Разбор падения, план большой задачи | DeepSeek V4.1 Flash | max |
| Ревью теста (субагент `test-reviewer`) | **другая** модель, не та, что писала | high |
| Простые правки, форматирование, оглавление | любая | low |

Ревью другой моделью снижает общие «слепые пятна» автора и ревьюера. В Qwen Code это поле `model:`
в `.qwen/agents/test-reviewer.md`, например `model: openai:glm-5.3-flash` (значение после двоеточия — `id` из настроек).
Прогоните контрольные задачи из `02-agent-kit/README.md` на обеих моделях и закрепите распределение по фактам.
