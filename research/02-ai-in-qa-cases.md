Собрано по публичным источникам на октябрь 2026. Цифры — со слов компаний, методики не всегда раскрыты.

## Зарубежные исследования
- **Meta TestGen-LLM** (Instagram, Facebook): каждый сгенерированный тест проходит фильтры «собирается → проходит несколько раз подряд → повышает покрытие». 75% собрались, 57% стабильно прошли, 25% подняли покрытие, 73% рекомендаций приняли инженеры. [arxiv.org/abs/2402.09171](https://arxiv.org/abs/2402.09171v1)
- **Meta ACH** (генерация под мутанты): 73% тестов приняты; 49% принятых **не добавили покрытия строк** — покрытие не мера пользы теста. [arxiv.org/html/2501.12862](https://arxiv.org/html/2501.12862v1)
- **Meta JiT catching tests** (2026): оценщик «LLM + правила» снизил нагрузку на ревью ~на 70%; из 41 кандидата в баги реальными оказались 8 — главная метрика — доля ложных срабатываний. [arxiv.org/abs/2601.22832](https://arxiv.org/abs/2601.22832v1)
- **Промышленный конвейер user story → Gherkin → Cypress**: 95% сценариев признаны полезными; из скриптов 60% годны сразу, 8% с мелкими правками, 24% перегенерированы, 8% выброшены. [arxiv.org/abs/2504.07244](https://arxiv.org/abs/2504.07244v1)
- **Кейсы из SRS цепочкой промптов** (по одному use case за раз): 87,7% валидных. [arxiv.org/abs/2412.03693](https://arxiv.org/abs/2412.03693)
- Осмысленные имена тестов и переменных повышают корректность сгенерированных проверок до 16 п.п. [arxiv.org/html/2410.21136](https://arxiv.org/html/2410.21136v1)

## Как ИИ-тесты врут: типовые сбои и защита

| Сбой | Защита в наборе |
|---|---|
| Выдуманные локаторы и API (по шаблонам из обучения, а не по живому DOM) | Локатор только из снимка/кода/codegen, иначе `TODO(locator)` |
| **Ослабление проверок и удаление тестов ради зелёного** (равенство → «истинно», упавший тест удалён) | Железное правило 3; ревью ищет изменения проверок; «докажи, что падает» |
| Тест закрепляет текущее (багованное) поведение вместо требования | Генерация от кейса и требований, литералы из кейса |
| Тестовые «запахи»: магические числа, «рулетка» проверок без сообщений, пустые тесты | Чек-лист `test-review`, строка «Ловит:» |
| Флаки: неупорядоченные результаты, копирование флаки-паттернов из контекста | Сначала починить флаки в эталонах; 3 прогона подряд; никаких пауз |
| Длинные сценарии обрезаются | Один кейс — одно поведение; > 15 шагов — разбить |
| Бесконечные циклы «починки» | Не больше 3 итераций, затем отчёт человеку |

Источники по сбоям: [arxiv.org/pdf/2605.01471](https://arxiv.org/pdf/2605.01471), [arxiv.org/html/2410.10628](https://arxiv.org/html/2410.10628v2), [arxiv.org/html/2601.08998](https://arxiv.org/html/2601.08998v1), [habr.com/ru/articles/902038](https://habr.com/ru/articles/902038).

## Что из этого следует для вашего продукта
1. **Контекст важнее модели.** Все успешные кейсы держатся на примерах из *своего* репозитория (RAG у Сбера, README у Росгосстраха). Отсюда `AGENTS.md`, `docs/architecture.md`, эталонный тест.
2. **Маленькие шаги.** План → код → компиляция → запуск → исправление, с лимитом итераций (Диасофт, РСХБ, Playwright planner → generator).
3. **Человек принимает решение.** Яндекс и Альфа: автономия без ревью в банке не проходит. Генерация предлагает, человек одобряет.
4. **Мерить пользу, а не объём:** доля принятых без правок (ориентир 60–70%), время ревью, доля флаки, сколько настоящих дефектов поймали автотесты.
5. **Учить людей.** У Яндекса обучение удвоило использование; у РСХБ джуны без навыка ревью стали медленнее.
6. **Банковская специфика — в базу знаний.** Модель сама не знает про роли, аудит и нормативы (Совкомбанк).

## Инструменты, которые работают без интернета
- **Playwright MCP** (`@playwright/mcp`) — управление браузером через aria-снимки, без модели зрения; есть `--codegen java`. **playwright-cli** со скиллами экономнее по токенам: схемы инструментов MCP ~3,6 тыс. токенов против ~68 у CLI-скилла — важно для локальной модели. [github.com/microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp), [github.com/microsoft/playwright-cli](https://github.com/microsoft/playwright-cli)
- **Playwright Test Agents** (planner / generator / healer, Playwright 1.56) генерируют **только TypeScript**. Для Java переносятся идеи: план в Markdown → генерация с проверкой локаторов вживую → «лечение» по трассе с одобрением человека. [playwright.dev/docs/test-agents](https://playwright.dev/docs/test-agents)
- **Allure TestOps** с 26.1.1 — встроенный MCP-сервер (бета): создание и правка тест-кейсов, поиск по AQL. Есть ли в self-hosted — в документации не сказано. [docs.qameta.io/allure-testops/howto/mcp](https://docs.qameta.io/allure-testops/howto/mcp/)
- **Test IT** 5.7 (on-prem, апрель 2026) — встроенная ИИ-генерация до 30 кейсов за запуск и генерация комбинаций параметров. Какие модели поддерживает и есть ли импорт Markdown — не подтверждено. [habr.com/ru/articles/1020290](https://habr.com/ru/articles/1020290)
- **Healenium** (самолечение локаторов) — только Selenium, для Playwright не подходит.
