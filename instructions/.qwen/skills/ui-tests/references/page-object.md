# Page Object в проекте

Образец — `pages/PilotsPage.java`, `pages/PilotForm.java`, `pages/components/DataTable.java`.

## Что делает Page Object
- **Действия** пользователя: `open()`, `clickCreate()`, `fill(data)`, `save()`. Имя — что делает пользователь, а не как (`save()`, а не `clickButtonSaveInFooter()`).
- **Локаторы для проверок**: `notification()`, `rowByName(name)`, `coverageError()` — возвращают `Locator`, тест проверяет их через `assertThat`.
- **Переходы**: действие, после которого открывается другой экран или диалог, возвращает его объект (`clickCreate()` → `PilotForm`). Действие на том же экране возвращает `this` для цепочки.
- `@Step` на действиях — Allure-отчёт читается как ручной кейс.

## Чего Page Object не делает
- **Не проверяет бизнес-результат.** `assertThat(...).containsText("Пилот создан")` — в тесте. Почему: один и тот же PO нужен и позитивному, и негативному тесту. Исключение — `open()`: ждёт признак загрузки (заголовок), иначе следующие действия гоняются со страницей.
- **Не ходит в БД, API и моки.** Это другие слои.
- **Не содержит пауз и ретраев.** Playwright сам ждёт actionability.
- **Не хранит тестовые данные.** Данные приходят параметром (`fill(PilotData data)`).

## Компоненты вместо наследования
Повторяющиеся блоки — отдельные классы, которые получают корневой `Locator`:
```java
public final class DataTable {
    private final Locator root;
    public DataTable(Locator root) { this.root = root; }
    public Locator row(String uniqueText) {
        return root.getByRole(AriaRole.ROW).filter(new Locator.FilterOptions().setHasText(uniqueText));
    }
}
// в странице
this.table = new DataTable(page.getByTestId("pilots-table"));
```
Кандидаты в компоненты: таблица, диалог подтверждения, фильтры, пагинация, меню, выпадающий список.
`BasePage` допустим только для действительно общих мелочей (уведомление, хлебные крошки); цепочки наследования
глубже одного уровня не делаем: их трудно читать и человеку, и модели.

## Локаторы внутри PO
- Корень диалога/блока ищется один раз, остальное — внутри него: `dialog.getByLabel("Название")`.
- Внутри `Locator` — `Locator.GetByRoleOptions`, на `Page` — `Page.GetByRoleOptions` (частая ошибка компиляции).
- Локатор — поле или метод? Метод, если зависит от параметра (`rowByName(name)`), иначе можно поле. Локаторы ленивые: создание не обращается к странице.
- Тексты кнопок и подписей — ровно как в UI. Если в проекте несколько языков интерфейса — `data-qa`.

## Кастомные элементы
- Нативный `<select>` — `selectOption(...)`. Кастомный список: клик по полю → `page.getByRole(AriaRole.OPTION, ...setName(значение)).click()`.
- Дата-пикер — вводить текстом в поле, если оно позволяет; иначе метод компонента `pick(LocalDate)`.
- Загрузка файла — `setInputFiles(Path)` на `input[type=file]`.
- Таблица с виртуальной прокруткой — фильтровать таблицу по уникальному имени, а не прокручивать.

## Размер
Один PO — один экран или диалог. Больше ~150 строк — выдели компоненты.
