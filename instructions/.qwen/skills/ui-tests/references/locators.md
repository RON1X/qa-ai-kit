# Локаторы: откуда брать и как писать

Главная причина «сгенерированный тест не работает» — выдуманные локаторы: модель подставляет
селекторы, похожие на те, что видела в обучающих данных, а не те, что есть на странице.
Поэтому локатор берётся только из источника правды.

## Источники правды (по порядку)

1. **Существующий Page Object** раздела. Не дублируй локатор — добавь метод в PO.
2. **Aria-снимок страницы.** Это дерево ролей и имён, ровно то, на что опираются `getByRole`/`getByLabel`.
   Как снять — скилл `playwright-browser` (Playwright MCP `browser_snapshot`, `playwright-cli snapshot`,
   `page.ariaSnapshot()` из Java, трасса упавшего теста). Снимки храним в `docs/snapshots/<страница>.yml`.
3. **Codegen** — человек кликает, Playwright пишет код с локаторами:
   `mvn exec:java -e -D exec.mainClass=com.microsoft.playwright.CLI -D exec.args="codegen --target java <url>"`.
   С сохранённой сессией: добавить `--load-storage=target/.auth/admin.json`.
4. **Нет доступа ни к чему** → `// TODO(locator): кнопка «Сохранить» в диалоге «Новый пилот»` и вопрос человеку.

## Как читать aria-снимок

```yaml
- dialog "Новый пилот":
  - textbox "Название"
  - combobox "Стратегия"
  - spinbutton "Процент охвата"
  - button "Сохранить"
```
→
```java
Locator dialog = page.getByRole(AriaRole.DIALOG, new Page.GetByRoleOptions().setName("Новый пилот"));
dialog.getByLabel("Название");
dialog.getByRole(AriaRole.BUTTON, new Locator.GetByRoleOptions().setName("Сохранить"));
```
Внимание к типам: на странице — `Page.GetByRoleOptions`, внутри локатора — `Locator.GetByRoleOptions`.

## Приоритет

| # | Способ | Когда |
|---|---|---|
| 1 | `getByRole(роль, setName(...))` | кнопки, ссылки, заголовки, диалоги, строки таблиц, вкладки |
| 2 | `getByLabel(...)` | поля ввода с подписью |
| 3 | `getByText(...)` | статичный текст, сообщения |
| 4 | `getByTestId(...)` | таблицы, контейнеры, иконки без текста. Атрибут проекта: **[ЗАПОЛНИТЬ: data-qa]** |
| 5 | CSS | только с комментарием, почему 1–4 не подходят |

## Правила
- Ищи внутри контейнера: сначала диалог/строка/карточка, потом элемент в нём.
- Строку таблицы — по уникальному тексту: `getByRole(ROW).filter(new Locator.FilterOptions().setHasText(name))`.
- `first()`/`nth()` — только с комментарием, почему элементов несколько и почему нужен именно этот.
- Нет доступного имени у важного элемента — заведи задачу фронту на `data-qa`, временно `getByTestId`/CSS с `TODO`.
- Не используй сгенерированные классы стилей и XPath по позиции.

## Если локатор «не находится» во время запуска
Это не повод добавлять паузу. Открой трассу (`show-trace`) и посмотри DOM в момент шага:
элемент в другом фрейме? в другом диалоге? имя отличается регистром или пробелом? страница не та?
