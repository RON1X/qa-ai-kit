# Метрики проекта автотестов

Числа берутся **только из вывода `scripts/TestMetrics.java`** (или из Allure). Не считай тесты «на глаз» по файлам
и не округляй: если скрипт что-то не посчитал — так и напиши.

## Запуск
```bash
# статические метрики + покрытие ручных кейсов
java scripts/TestMetrics.java --src src/test/java --cases test-cases --out target/metrics.md
# плюс результаты прогона (после mvn test или из артефактов CI)
java scripts/TestMetrics.java --src src/test/java --cases test-cases --allure target/allure-results --out target/metrics.md
```
Нужна только Java 11+ (запуск одного файла без компиляции). Отчёт — Markdown в UTF-8.

## Что считает скрипт
| Блок | Метрики | Откуда |
|---|---|---|
| Исходники | тестовые методы и классы; тест-случаи с раскрытием `@CsvSource`/`@ValueSource`; отключённые | аннотации JUnit |
| Слои | ui / api / db / e2e | `@Tag`, иначе пакет `tests/ui/`, `tests/api/` |
| Критичность | BLOCKER … TRIVIAL, «не указана» | `@Severity` |
| Фичи | эпик / фича | `@Epic`, `@Feature` |
| Качество разметки | без `@Severity`, без `@TmsLink`, без слоя | — |
| Техдолг | паузы, XPath, `TODO(locator)` | текст исходников |
| Ручные кейсы | всего, по приоритету, покрыто автотестами, кейсы высокого приоритета без автотестов, `@TmsLink` без кейса | `test-cases/**/TC-*.md` ↔ `@TmsLink("Раздел/Подраздел/TC-001")` |
| Прогон | статусы, pass rate, перезапуски, флаки, длительность (медиана, 90-й перцентиль), самые долгие, упавшие | `allure-results/*-result.json` |

Ограничения: число случаев `@MethodSource`/`@EnumSource` видно только после прогона; аннотации внешнего класса не
переносятся на `@Nested`; флаки определяются в пределах одного прогона (метка Allure или разный исход перезапусков).

## Как отвечать
1. Запусти скрипт, прочитай отчёт.
2. Ответ — 3–5 строк выводов с числами из отчёта, затем ссылка на файл отчёта. Пример:
   ```
   Автотестов 214 (UI 120, API 82, DB 12), отключено 6.
   Покрыто 61% ручных кейсов; высокий приоритет — 78%, без автотестов 9 кейсов (список в отчёте).
   Прогон: pass rate 93.4%, флаки 5, медиана 8.2 с, самые долгие — UI-тесты раскатки.
   Разметка: 17 тестов без @Severity, 23 без @TmsLink.
   Отчёт: target/metrics.md
   ```
3. Если просили рекомендации — не больше 3, каждая со ссылкой на число: «9 кейсов высокого приоритета без автотестов → автоматизировать первыми».

## Какие метрики полезны, а какие вводят в заблуждение
| Полезно | Почему |
|---|---|
| Покрытие кейсов высокого приоритета | показывает риск там, где он важен |
| Доля флаки и их список | флаки обесценивают красный прогон: у Google ~84% переходов «прошёл → упал» связаны с флаки-тестами |
| Медиана и 90-й перцентиль длительности, самые долгие | что ускорять |
| Тесты без `@Severity`/`@TmsLink` | без разметки отчёт и покрытие не построить |
| Техдолг (паузы, XPath) | прямые причины нестабильности |

| Вводит в заблуждение | Почему |
|---|---|
| Число тестов само по себе | сто тестов на одну форму не равны десяти на десять разделов |
| Pass rate без флаки | 95% при 10% флаки — не стабильный набор |
| «Покрытие кода» для e2e | e2e измеряют сценарии, а не строки кода |

## Тренд
Сохраняй отчёты прогонов (`target/metrics.md` в артефакты CI) и сравнивай: рост флаки, падение покрытия
высокого приоритета, рост длительности — сигналы. Для истории в Allure 2 копируйте папку `history` прошлого отчёта
в `allure-results` перед генерацией нового.
