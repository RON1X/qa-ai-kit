# QA AI Kit: инструкции для ИИ-агента по автотестам

Набор для работы с внутренней моделью (GLM-5.3-Flash, DeepSeek V4.1 Flash) через агента (Qwen Code и др.) или чат:
ручные кейсы, UI / API / БД автотесты, Page Object, Playwright MCP, метрики проекта, стиль ответов.
Стек: Java 17, Maven, JUnit 5, Playwright for Java, AssertJ, Allure, Owner, Lombok, Jackson, PostgreSQL.

## Структура
| Папка | Для кого | Что |
|---|---|---|
| `instructions/` | модель | **то, что копируется в проект**: `AGENTS.md`, 10 скиллов, стили ответа, команды, субагент-ревьюер, шаблоны docs, скрипты; плюс `guides/` и `chat/` для вас |
| `agent/` | модель | пример единого агента поверх `instructions/`: роль и сценарии (`QWEN.md`), одобрение плана настройкой, 4 субагента (explorer, test-writer, test-reviewer, failure-analyst), модели по ролям, 12 контрольных задач |
| `examples/` | вы и модель | эталонный каркас под стек: Owner-конфиг, Playwright-расширения, API-клиент на Jackson + Lombok, JDBC-клиент, мок-слой, Page Object с компонентами, эталонные UI- и API-тесты |
| `research/` | вы | ресерч и план внедрения: Superpowers, кейсы компаний, Playwright, БД, моки, Qwen Code, DeepSeek/GLM, SDD и спеки, как писать инструкции, стиль ответа, метрики |

С чего начать: `research/00-implementation-plan.md` → `instructions/README.md` → `agent/README.md` → `examples/`.

## Как подтянуть на работе
```bash
git clone https://github.com/RON1X/qa-ai-kit.git
cd qa-ai-kit
./install.sh ../my-autotests          # путь к вашему репозиторию автотестов
```
`install.sh` копирует `instructions/` в корень репозитория автотестов и **не перезаписывает** существующие файлы
(`guides/` и `chat/` не копирует — это справка для человека). Дальше — шаги из `instructions/README.md`.

Обновить набор:
```bash
cd qa-ai-kit && git pull
./install.sh ../my-autotests --update
```
`--update` перезаписывает только «библиотеку» — скиллы, команды, стили, субагентов, скрипты. Ваши `AGENTS.md`,
`docs/` и `.qwen/settings*` не трогает. Правили скилл под себя — сначала посмотрите разницу.

GitHub из рабочей сети недоступен — **Code → Download ZIP** на странице репозитория, перенести разрешённым способом.

## Главные решения
1. **AGENTS.md — только неочевидное.** Исследование ETH Zurich (2026): обзоры репозитория агентам не помогают и удорожают работу; помогают команды и нестандартные правила. Поэтому в `AGENTS.md` — стиль ответа, команды и 11 правил с причинами, детали — в скиллах.
2. **Стиль ответа — механизмом, а не просьбой.** Стили Qwen Code `brief` / `detailed` / `tech` напоминаются модели на каждом ходу; разово — `кратко:`, `подробно:`, `тех:`.
3. **Spec-first без тяжёлых инструментов.** Ручной кейс — спека одного теста; для больших задач — короткая спека с критериями в EARS и одобрением до кода (скилл `test-spec`).
4. **«Докажи, что тест ловит дефект»** (из TDD в Superpowers): испортить ожидание — тест обязан упасть.
5. **Локаторы — из снимка страницы** (Playwright MCP / CLI), а не из головы модели.
6. **JSON — Jackson, а не `setData(объект)`**: Playwright сериализует объекты встроенным Gson и игнорирует аннотации Jackson и Lombok-билдеры.
7. **Клиент API не проверяет** — проверяет тест; негатив пишется через `toBuilder()`.
8. **БД: read-only для проверок, запись только по id и `AT-`**; SQL в файлах с `?`.
9. **Метрики — скриптом** (`TestMetrics.java`, без зависимостей): модель пересказывает числа, а не считает.
10. **Механические запреты — скриптом** (`guard-tests.sh`): паузы, `@Disabled`, опасный SQL.
11. **Ревью свежим контекстом и другой моделью** — субагент только на чтение.

## Что проверено
- **Java-примеры** прошли проверку типов `javac` против исходников Playwright Java 1.63.0, JUnit 5.14.1, AssertJ, Allure 2.35.5, Owner, Jackson 2.20, Awaitility; Lombok-классы — через сгенерированный эквивалент (getters, builder, `toBuilder`). Проверка ловит внесённые ошибки и помогла исправить реальную (тип опций `getByRole` внутри локатора). **Против живого приложения не запускались**: домен, локаторы, таблицы и пути API — вымышленный пример.
- **`TestMetrics.java`** запущен на примерах, граничных случаях разбора и искусственных результатах Allure.
- **Скрипты**: `install.sh` (установка, повтор, обновление после правок, ошибки), `guard-tests.sh` (репозиторий с нарушениями и без), `find-polluter.sh` и `flaky-check.sh` (имитация Maven), `db-schema-to-md.sql` (PostgreSQL 16), `index-framework.sh` (на примерах).
- **Имена инструментов Playwright MCP / CLI и настройки Qwen Code** (включая Output Styles) сверены с их актуальной документацией; с вашей моделью не запускались.
- **`SberMockClient` — шаблон**: API SberMock заполняет человек (`TODO(SberMock)`).
