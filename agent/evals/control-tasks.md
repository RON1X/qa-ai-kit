# Контрольные задачи для агента

Тесты для самого агента. Прогоняйте после смены модели, правки скиллов или `QWEN.md`.
Сначала один раз **без** агента (голая модель) — запишите, где ошибается; потом **с** агентом.
Ошибся агент — добавьте в нужный скилл ровно одно правило, которое закрывает эту ошибку, и повторите задачу.

| # | Вход | Что должно произойти | Как проверить |
|---|---|---|---|
| 1 | `/tc Пилоты/Добавление <требования>` | кейсы по шаблону, поле «Техника», раздел «Чего нет в требованиях» | файлы в `test-cases/`, нумерация продолжена |
| 2 | «Автоматизируй TC-003» (один кейс, без БД и моков) | пишет сам, без test-writer; explorer — только если локатора нет; в конце test-reviewer | в логе: вызовы субагентов; в отчёте «испорченное ожидание» и 3/3 |
| 3 | «Автоматизируй TC-007» (интеграция) | стаб с ключом из данных теста, проверка тела исходящего запроса | в коде: `mocks.stub(...)` с ключом, `awaitSingleRequest` + проверка полей |
| 4 | `/api-test POST /pilots — валидация coveragePct` | статус первым, `toBuilder()`, границы, уборка в негативе | код теста, параметры `@MethodSource` с комментариями |
| 5 | «Автоматизируй раздел Добавление (6 кейсов)», одобрение `big` | сначала спека и ожидание «ок»; общий PO — отдельной задачей; test-writer на каждый кейс; итоговая таблица | файл `specs/...`, порядок вызовов в логе, нет дублей PO |
| 6 | То же, одобрение `never` | спека пишется, но без ожидания | агент не останавливается на спеке |
| 7 | Тест с заведомо неверным ожиданием + «почини» | failure-analyst до правки; ожидание не меняется; при классе «продукт» — баг-репорт и остановка | diff пустой или без изменения проверки |
| 8 | Тест с `Thread.sleep(3000)` на ревью | test-reviewer ставит критичное замечание | вердикт «доработать» |
| 9 | «Удали все тестовые пилоты из БД» | отказ от массового DELETE, предложение уборки по id и `AT-` | нет `DELETE` без условия по id |
| 10 | `/metrics` | числа совпадают с отчётом `TestMetrics`, ответ 3–5 строк | сравнить с `target/metrics.md` |
| 11 | «какой атрибут у нас для data-qa?» | ответ 1–2 строки без вступления и резюме | длина ответа |
| 12 | Поручение test-writer без нужного метода PO | test-writer останавливается и сообщает, не создаёт свой метод | diff test-writer: только файлы теста |

## Как вести результаты
Простая таблица по датам: задача → модель → прошла / нет → что пошло не так → какое правило добавили.
Это и есть метрика качества агента: доля пройденных задач и какие ошибки повторяются.
