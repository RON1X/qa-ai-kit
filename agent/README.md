# Единый QA-агент: пример сборки

Как собрать из `instructions/` одного агента с субагентами. Это надстройка: скиллы, команды, стили и скрипты
берутся из `instructions/`, здесь — только то, что превращает набор в агента. Пример под Qwen Code;
для другого инструмента переносится по смыслу (см. ниже).

## Устройство
```
                 ┌──────────────────────────── главный агент (QWEN.md) ────────────────────────────┐
запрос ─────────▶│ выбирает сценарий по таблице · сам пишет 1–3 теста · оркеструет большие задачи │
                 └───┬───────────────┬─────────────────────┬─────────────────────┬────────────────┘
                     │               │                     │                     │
                 explorer       test-writer           test-reviewer        failure-analyst
              (страницы,      (один кейс на вызов,   (только чтение,      (разбор падения,
               локаторы)       только в больших        другая модель)       без правок кода)
                               задачах)
```
| Роль | Файл | Модель | Может менять код |
|---|---|---|---|
| Главный агент | `QWEN.md` + `AGENTS.md` проекта | DeepSeek V4.1 Flash | да |
| explorer | `.qwen/agents/explorer.md` | DeepSeek V4.1 Flash | нет |
| test-writer | `.qwen/agents/test-writer.md` | DeepSeek V4.1 Flash | только свой тест |
| test-reviewer | `.qwen/agents/test-reviewer.md` | GLM-5.3 | нет |
| failure-analyst | `.qwen/agents/failure-analyst.md` | DeepSeek V4.1 Flash | нет |
| Мелочи (подсказки) | `fastModel` | Qwen 3.6 | — |

Почему так:
- **Главный пишет сам маленькие задачи.** Написание теста — плотный цикл «код → ошибка → правка», и передача задачи между агентами теряет детали.
- **Оркестрация — для больших.** К восьмому тесту подряд контекст забит логами; свежий test-writer на каждый кейс держит качество.
- **Отдельный контекст для громкого.** Снимки страниц (explorer) и логи разбора (failure-analyst) не засоряют главного.
- **Ревью другой моделью.** У автора и ревьюера разные слепые пятна.

## Установка
```bash
./install.sh ../my-autotests                 # instructions/: правила, скиллы, команды, стили, скрипты
cp -r agent/. ../my-autotests/               # QWEN.md, субагенты, настройки ролей, evals
cp ../my-autotests/.qwen/settings.example.json ../my-autotests/.qwen/settings.json
```
`cp` заменит `test-reviewer.md` и `settings.example.json` из `instructions/` версиями с моделями по ролям — так и задумано.
Дальше: id моделей и `baseUrl` в `settings.json` — по данным вашей платформы; `contextWindowSize` — по `max-model-len` сервера.

## Настройки
- **Одобрение плана** — в начале `QWEN.md`: `always` | `big` | `never`; там же порог «большой задачи».
- **Модели по ролям** — строка `model:` во frontmatter субагента (`openai:<id>` из `settings.json`).
- **Глубина рассуждения по ролям.** У субагентов Qwen Code нет своего поля для этого — она задаётся у модели (`extra_body.reasoning_effort`). Чтобы explorer думал `low`, а failure-analyst — `max` на одной модели, попросите на сервере vLLM несколько имён для неё (`--served-model-name deepseek-flash deepseek-flash-max`) и заведите в `settings.json` две записи с разным `reasoning_effort`. Без этого все роли DeepSeek работают на `high` — это нормальный старт.
- **Отключить субагента** — удалить или переименовать его файл; главный агент сделает ту же работу сам по скиллу.

## Важные детали Qwen Code
- Субагенты по умолчанию работают **в фоне**. В `QWEN.md` главному агенту велено вызывать их с `run_in_background: false`, иначе он продолжит, не дождавшись ответа.
- Субагент не видит разговор главного — всё нужное должно быть в поручении (форма поручения — в `QWEN.md`).
- `QWEN.md` и `AGENTS.md` читаются оба (`context.fileName` в настройках): в `AGENTS.md` — факты проекта, в `QWEN.md` — роль агента.

## Другой инструмент вместо Qwen Code
- Содержимое `QWEN.md` добавьте в конец `AGENTS.md`.
- Субагентов перенесите в формат инструмента: суть каждого — описание (когда звать), запреты (какие инструменты нельзя), модель, тело (порядок работы и формат ответа).
- Нет субагентов — оставьте одного агента: сценарии из `QWEN.md` работают и без делегирования, просто медленнее на больших задачах.

## Проверка
`evals/control-tasks.md` — 12 контрольных задач: что подать, что должно произойти, как проверить.
Прогоняйте после смены модели и правок. Здесь агент с вашими моделями не запускался — эти задачи и есть его первая проверка.
