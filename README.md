# QA AI Kit: ИИ-помощник для ручных кейсов и UI e2e автотестов

Пакет для переноса в закрытый контур. Всё в Markdown и Java, интернет не нужен: достаточно Nexus и зеркала npm.
Контекст: веб-админка банковских стратегий (Пилоты → Симуляции → Внедрения → История изменения),
~30% функциональности — интеграции (стабы SberMock), стек Java + Playwright + Maven + JUnit 5, нужна работа с БД,
внутренние модели DeepSeek V4.1 Flash и GLM-5.3-Flash (подойдёт и Qwen), агент — Qwen Code или любой с поддержкой AGENTS.md/SKILL.md.

## Что внутри и в каком порядке читать
| Папка | Для кого | Что |
|---|---|---|
| `01-plan/implementation-plan.md` | вы | **начать отсюда**: фазы, критерии готовности, метрики, риски, вопросы к коллегам |
| `00-research/` | вы | ресерч: Superpowers, кейсы компаний, Playwright Java, БД, моки, Qwen Code, **DeepSeek V4.1 Flash и GLM-5.3-Flash** (`07-deepseek-glm.md`) |
| `02-agent-kit/` | модель | **сам продукт**: `AGENTS.md`, 6 скиллов, команды, субагент-ревьюер, шаблоны docs, скрипты |
| `03-java-examples/` | вы и модель | эталонный каркас: расширения, БД, мок-слой, Page Object, 2 эталонных теста |

## Интересные решения, которые стоит забрать в первую очередь
1. **«Докажи, что тест ловит дефект».** Адаптация TDD из Superpowers: продукт уже написан, поэтому ломаем не код, а ожидание — тест обязан упасть с понятным сообщением. Отсекает самую частую беду ИИ-тестов — зелёные тесты, которые не могут упасть.
2. **Строка `Ловит:` в каждом тесте** («назови поломку» из Superpowers). Нет ответа — нет теста.
3. **Корреляция с моками через бизнес-данные.** Браузер не может пометить запрос бэкенда во внешнюю систему, поэтому ключ — уникальное значение, которое тест вводит в форму (код сегмента), а стаб матчит тело по нему. Параллельные тесты на общем SberMock не мешают друг другу; глобальный reset запрещён.
4. **Проверка исходящего запроса**, а не «мок вызван»: что именно админка отправила во внешнюю систему.
5. **Уборка регистрируется до действия и по уникальному имени** — срабатывает, даже если тест упал на середине. SQL-уборка с предохранителем `name like 'AT-%'`.
6. **Два пользователя БД**: только SELECT для проверок, ограниченная запись для уборки.
7. **Архитектурный README генерирует агент, вычитывает человек** (опыт Росгосстраха: вместо двух недель правок первого PR).
8. **«RAG для бедных»** — `scripts/index-framework.sh` делает оглавление готовых методов; локальная модель читает одну страницу вместо всего репозитория и не плодит дубли.
9. **Механические запреты — скриптом** (`scripts/guard-tests.sh`): паузы, `@Disabled`, TRUNCATE, DELETE без предохранителя, удалённые проверки.
10. **Ревьюер со свежим контекстом** — субагент только на чтение, который не верит отчёту автора.
11. **«Чего нет в требованиях»** при генерации кейсов — до 5 вопросов аналитику (Review Focus из Superpowers).
12. **Контрольные задачи для инструкций** — инструкции тестируются как код: прогон без скилла и со скиллом.

## Как подтянуть на работе
```bash
git clone https://github.com/RON1X/qa-ai-kit.git
cd qa-ai-kit
./install.sh ../my-autotests          # путь к вашему репозиторию автотестов
```
`install.sh` копирует набор для агента (`02-agent-kit`) в корень репозитория автотестов и **не перезаписывает**
существующие файлы. Затем:
1. Прочитать план, пройти Фазу 0 (вопросы к коллегам — в конце плана).
2. `cp .qwen/settings.example.json .qwen/settings.json` — вписать адрес и `id` моделей.
3. Заполнить все `[ЗАПОЛНИТЬ]` и `TODO(SberMock)` — это делает человек.
4. `03-java-examples` — образец для своего каркаса: переносите классы вручную, адаптируя пакеты и домен.

**Обновить набор** после изменений в этом репозитории:
```bash
cd qa-ai-kit && git pull
./install.sh ../my-autotests --update
```
`--update` перезаписывает только «библиотеку» — скиллы, команды, субагентов, скрипты. Ваши `AGENTS.md`, `docs/`
и `.qwen/settings*` не трогает никогда. Правили скилл под себя — сначала посмотрите разницу, правки будут заменены.

Если GitHub из рабочей сети недоступен: на github.com → **Code → Download ZIP**, перенести архив разрешённым способом,
распаковать и запустить тот же `install.sh`.

## Что проверено, а что нет
- **Java-примеры** прошли проверку типов против исходников Playwright Java 1.63.0, JUnit 5.14.1, Allure 3.0.0, AssertJ, Awaitility, Gson; Jdbi и HikariCP — против сверенных по исходникам сигнатур. Проверка нашла и помогла исправить одну реальную ошибку (тип опций `getByRole` внутри локатора).
- **Не запускались против живого приложения**: локаторы, тексты, таблицы БД и пути интеграций — **вымышленный пример** домена. Замените их своими.
- **`SberMockClient` — шаблон**: пути и поля API помечены `TODO(SberMock)`, публичной документации по SberMock нет и не искалась.
- **Скрипты** проверены: `guard-tests.sh` — на тестовом git-репозитории с нарушениями и без; `find-polluter.sh` и `flaky-check.sh` — с имитацией Maven; `db-schema-to-md.sql` — на PostgreSQL 16; `index-framework.sh` — на эталонном коде.
- **Настройки Qwen Code** сверены с документацией Qwen Code (октябрь 2026), но не запускались с вашей моделью.
- **Версии зависимостей** — актуальные на октябрь 2026 по mvnrepository и GitHub; наличие в вашем Nexus проверьте.
- Цифры из кейсов компаний — со слов компаний, методики часто не раскрыты.
