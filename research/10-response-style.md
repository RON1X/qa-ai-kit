# Управление длиной и стилем ответа модели

Задача: модель на простые вопросы отвечает «портянками». Как сделать короче (или длиннее, техничнее) — постоянно и разово.

## Почему модели многословны
**YapBench** (arXiv:2601.00624, 2026): 304 вопроса, на которые достаточно короткого ответа, 76 моделей.
- Лишняя длина отличается между моделями примерно на порядок; это следствие дообучения, а не размера модели (gpt-3.5-turbo оказался одним из самых кратких).
- Типовые причины: на неясный запрос модель «заполняет пустоту» вместо уточнения; на фактический вопрос добавляет оговорки и контекст; на задачу «одна строка кода» — оформление и объяснения.
- Режим рассуждения на медианную длину ответа почти не влияет.
- **GLM-4.5 был самым многословным в общем рейтинге**, а GLM-4.7 — среди самых кратких на задачах «одна строка кода». Вывод: многословность зависит и от модели, и от типа вопроса — нужны шаблоны под тип ответа.

## Что работает
| Приём | Источник |
|---|---|
| Говорить, что делать, а не что не делать: «пиши связными абзацами» вместо «не используй markdown» | Anthropic, Prompting best practices |
| Стиль промпта переносится на ответ: меньше разметки в инструкции — меньше в ответе | Anthropic |
| Объяснять причину правила — модель обобщает её на похожие случаи | Anthropic |
| Конкретные рамки длины: «3–6 предложений или ≤5 пунктов», «≤2 предложения на да/нет», для больших задач — абзац + ≤5 пунктов «что изменено / где / риски / дальше / вопросы» | OpenAI, GPT-5.2 Prompting Guide |
| Не пересказывать запрос пользователя; не расширять задачу; неоднозначное — простейшая трактовка | OpenAI |
| Обновления о ходе работы — 1–2 предложения и только при смене этапа | OpenAI |
| Стиль, который напоминается на каждом ходу (Output Styles в Qwen Code), держится в длинной сессии | Qwen Code docs |
| Без «CRITICAL/MUST» — новые модели перегибают на агрессивные формулировки | Anthropic |

## Что не работает
- **`max_tokens` для сокращения.** Ответ обрывается; у рассуждающих моделей рассуждение и ответ делят бюджет — можно получить пустой ответ (`finish_reason=length`).
- **`reasoning_effort` для сокращения.** Он меняет глубину рассуждения, не длину видимого ответа.
- **Понижение temperature.** Для DeepSeek в режиме рассуждения игнорируется; Together AI для DeepSeek V4 Pro прямо предупреждает, что низкая температура может «схлопнуть» рассуждение и ухудшить ответ.

## Особенности моделей
- **DeepSeek V4.x**: рассуждение включено по умолчанию; для простых шагов его можно выключить (`reasoning_effort: none`) — ответ быстрее. Если рассуждение нужно — можно попросить «рассуждай кратко». Для длинного контекста: инструкции в начале, вопрос в конце. (Together AI, DeepSeek V4 quickstart)
- **GLM-5.3**: рассуждение всегда включено, `low` — ближайший к «выключено» вариант; жёсткие ограничения писать явно. (Z.ai docs, Together AI)

## Механизмы в инструментах
| Инструмент | Механизм |
|---|---|
| Qwen Code | **Output Styles**: встроенные `Concise`, `Proactive`, `Explanatory`, `Learning` и свои в `.qwen/output-styles/*.md` (frontmatter `name`, `description`, `keep-coding-instructions`); переключение `/output-style <имя>`, по умолчанию — `general.outputStyle`, разово — `--output-style`. Стиль напоминается на каждом ходу; к субагентам не применяется. |
| Любой агент | раздел «Как отвечать» в `AGENTS.md` |
| Чат | системный промпт / инструкции чата |
| Разово | переключатель в начале сообщения: `кратко:`, `подробно:`, `тех:` |

## Что сделано в наборе
- `instructions/.qwen/output-styles/brief.md` (по умолчанию), `detailed.md`, `tech.md`; `keep-coding-instructions: true`, чтобы не терять встроенные правила работы с кодом.
- Раздел «Как отвечать» в `AGENTS.md` и в `chat/system-prompt.md` с теми же переключателями.
- Шаблоны ответа под тип задачи в скиллах (отчёт по тесту, метрики — «3–5 строк с числами + путь к отчёту»).
- Гайд для человека — `instructions/guides/response-style.md`.
