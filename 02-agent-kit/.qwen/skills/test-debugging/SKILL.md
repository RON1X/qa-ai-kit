# Разбор падения автотеста

Адаптация методики systematic-debugging из Superpowers для UI e2e на общем стенде.

## Железный закон

```
НИКАКИХ ПРАВОК БЕЗ УСТАНОВЛЕННОЙ ПРИЧИНЫ.
```
Пауза, ретрай, ослабленная проверка без причины — это не починка, а прятание дефекта (возможно, в продукте).

## Фаза 1. Улики (до гипотез)
1. **Прочитай ошибку целиком**: сообщение, стек, строку теста, ожидаемое и фактическое значение.
2. **Вложения Allure**: скриншот в момент падения, трасса (`show-trace target/traces/<Класс>.<метод>.zip` — DOM, сеть и консоль на каждом шаге), SQL с параметрами, журнал мок-сервера по ключам теста.
3. **Воспроизведи**:
   - отдельно: `mvn test -Dtest=<Класс>#<метод>`;
   - несколько раз: `scripts/flaky-check.sh <Класс> 5`;
   - вместе с соседями по прогону (как в CI).
4. **Что изменилось**: `git log -10 --stat` в тестах; новая сборка на стенде; изменения справочников/данных; изменения стабов.
5. **Граница слоёв**: где данные перестают быть правильными? UI отправил → бэкенд записал → бэкенд отправил во внешнюю систему → мок ответил → UI показал. Проверь каждый переход по уликам, а не предположениям.

## Фаза 2. Классифицируй
| Класс | Признаки | Что делать |
|---|---|---|
| **Дефект продукта** | проверка верна по требованию, UI/БД/запрос не соответствуют | не трогать тест; оформить баг (шаблон ниже) |
| **Дефект теста: локатор** | элемент есть в трассе, но с другим именем/ролью; strict mode violation | исправить локатор по снимку |
| **Дефект теста: ожидание** | проверка до появления результата; пауза вместо условия | заменить на `assertThat`/`await` по условию |
| **Дефект теста: данные** | конфликт имён, чужие данные в выборке, зависимость от справочника | уникальные данные, фильтр по своему ключу |
| **Загрязнение** | падает только после определённых тестов | найти «загрязнителя»: `scripts/find-polluter.sh` |
| **Мок** | в журнале запрос есть, но стаб не сработал; ответ стаба устарел | сверить ключ, путь, приоритет; обновить стаб по каталогу |
| **Стенд** | 5xx у самой админки, недоступна БД, деплой во время прогона | перезапуск после восстановления; не править тест |

Сомневаешься между «продукт» и «тест» — сверь проверку с ручным кейсом и требованием. Тест прав, если прав кейс.

## Фаза 3. Одна гипотеза
- Сформулируй: «Причина — X, потому что улика Y».
- Проверь минимальным изменением **одной** переменной.
- Не подтвердилась — новая гипотеза из улик. Не накладывай правки друг на друга.

## Фаза 4. Починка и проверка
1. Одна правка — в причину, не в симптом.
2. `mvn -q test-compile`, затем `scripts/flaky-check.sh <Класс> 3` — все прогоны зелёные.
3. Если чинил проверку — заново пройди шаг «Докажи, что тест ловит дефект» из `autotest-writer`.
4. **Три неудачные попытки — стоп.** Это сигнал, что неверна модель происходящего (или архитектура теста). Отчёт человеку: улики, гипотезы, что пробовал.

## Флаки: ожидание по условию вместо пауз
| Ситуация | Вместо паузы |
|---|---|
| Ждём текст/элемент | `assertThat(locator).hasText(...)` / `.isVisible()` |
| Ждём уход спиннера | `assertThat(spinner).isHidden()` |
| Ждём навигацию | `page.waitForURL("**/pilots/**")` |
| Ждём ответ API админки | `page.waitForResponse(url -> ..., () -> button.click())` |
| Ждём строку в БД | `await().atMost(...).until(() -> dao.find(...), Optional::isPresent)` |
| Ждём запрос в мок | `mocks.awaitSingleRequest(path, key)` |
| Даты/таймеры на странице | `page.clock().setFixedTime(...)` |
| Случайные баннеры/оверлеи | `page.addLocatorHandler(баннер, b -> закрыть)` |

Пауза допустима, только если проверяется само время (например, автосохранение через 30 с) — и тогда сначала ждём условие, затем паузу с комментарием, откуда число.

## Шаблон баг-репорта (если дефект продукта)
```
Заголовок: <Раздел>: <что не так> при <условии>
Стенд / сборка: ...
Предусловия: ...
Шаги: 1. ... 2. ...
Ожидаемый результат (по требованию/кейсу <ссылка>): ...
Фактический результат: ...
Улики: скриншот, трасса, SQL и результат, исходящий запрос из журнала мока
Автотест: <Класс>#<метод> — падает стабильно N/N
```

## Красные флаги — вернись в Фазу 1
- «Добавлю sleep — пройдёт»
- «Поменяю проверку на contains»
- «Поставлю ретрай, и всё»
- «Наверное, стенд тормозит» (без улик)
- «Ещё одна попытка» после двух неудачных
