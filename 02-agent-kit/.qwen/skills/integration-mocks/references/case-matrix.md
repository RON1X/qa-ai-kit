# Матрица сценариев для интеграции

Заполняй для каждой интеграции из `docs/integrations.md`. Колонка «Уровень» решает, где живёт проверка:
UI e2e — дорого и медленно, поэтому туда идёт только то, что видит пользователь.

| # | Ответ внешней системы | Ожидаемое поведение админки | Что проверить | Уровень |
|---|---|---|---|---|
| 1 | 200, корректные данные | результат показан, данные сохранены | UI + БД + тело исходящего запроса | UI e2e |
| 2 | 200, пустой список / нулевые значения | понятное пустое состояние, без ошибок | UI | UI e2e |
| 3 | 200, нет необязательных полей | экран не падает, поле «—» | UI | UI e2e или API |
| 4 | 200, неизвестное значение enum | не падает, корректное отображение/сообщение | UI | API |
| 5 | 4xx бизнес-отказ (код ошибки) | сообщение с причиной, ничего не сохранено | UI + БД (отсутствие) | UI e2e |
| 6 | 4xx каждый прочий код | правильное сообщение | UI-текст | API / компонентный |
| 7 | 5xx | сообщение «сервис недоступен», без половинчатого сохранения | UI + БД | UI e2e |
| 8 | Разрыв соединения / битый ответ | как 5xx | UI + БД | UI e2e (один из двух) |
| 9 | Ответ дольше таймаута клиента | UI не висит, сообщение, состояние данных по требованиям | UI + БД | UI e2e |
| 10 | 503, затем 200 (повтор) | повтор выполнен, результат один | UI + число запросов + ключ идемпотентности одинаковый | UI e2e при наличии ретраев |
| 11 | Асинхронный ответ (callback) | статус обновился после callback | UI + БД с `await` | UI e2e |
| 12 | Двойное нажатие «Сохранить» | ровно один исходящий запрос / одна запись | число запросов в журнале + БД | UI e2e |

## Исходящий запрос — отдельный контракт
Для сценария 1 проверь сопоставление полей формы и запроса:

| Поле формы | Поле запроса | Пример значения | Проверено тестом |
|---|---|---|---|
| Код сегмента | `segmentCode` | `AT_SEG_1A2B3C4D` | `CreatePilotTest` |
| Продукт | `productCode` | `CONSUMER_LOAN` | `CreatePilotTest` |

## Пирамида для интеграций
- **UI e2e**: успех, видимые пользователю деградации, ключевые поля исходящего запроса.
- **API-тесты против того же мок-сервера**: все коды ошибок и комбинации полей.
- **Контрактные тесты** (Pact, Spring Cloud Contract) — если смежная команда готова: защищают от того,
  что ваш стаб перестал соответствовать реальной системе. Расхождение контракта — повод обновить стабы.
