## Пример: Сервис сегментов
| Поле | Значение |
|---|---|
| Что делает для админки | проверяет код сегмента и возвращает число клиентов |
| Какой UI-сценарий вызывает | Пилоты → Создать пилот → Сохранить |
| Метод и путь | `POST /segment-service/api/v1/segments/validate` |
| Ключ корреляции | `segmentCode` (тест генерирует `AT_SEG_XXXXXXXX`) |
| Таймаут клиента админки | 30 с |
| Ретраи / идемпотентность | нет |
| Класс стабов | `mock/SegmentServiceStubs.java` |

| Сценарий | HTTP | Тело (кратко) | Ожидаемое поведение админки |
|---|---|---|---|
| Успех | 200 | `status: VALID, clientsCount` | пилот создан, статус «Черновик» |
| Сегмент не найден | 404 | `errorCode: SEGMENT_NOT_FOUND` | «Сегмент не найден», форма открыта |
| Техническая ошибка | 500 | `errorCode: INTERNAL_ERROR` | «Сервис сегментов недоступен», пилот не сохранён |
| Таймаут | — | задержка 35 с | **[уточнить у аналитика]** |

Исходящий запрос:
```json
{"segmentCode": "AT_SEG_1A2B3C4D", "productCode": "CONSUMER_LOAN", "requestedBy": "autotest_admin"}
```
