# Шаблон тест-кейса

Копируй блок ниже целиком. Не удаляй разделы: если раздел пуст — напиши «—».
Поля «Уровень проверки» и «Интеграции» нужны, чтобы кейс можно было автоматизировать без догадок.

```markdown
# TC-<NNN>. <Название: что делаем и при каком условии>

| Поле | Значение |
|---|---|
| **Путь** | <Раздел>/<Подраздел>/... (фактическая глубина папки) |
| **Требование** | <ID или ссылка на пункт ТЗ/документации; если нет — «нет ссылки»> |
| **Приоритет** | Высокий / Средний / Низкий |
| **Тип** | Позитивный / Негативный / Граничный |
| **Техника** | Классы эквивалентности / Граничные значения / Таблица решений / Переходы состояний / Попарное / Сценарий использования |
| **Роль** | <роль пользователя, под которой выполняется кейс> |
| **Уровень проверки** | UI / UI + БД / UI + интеграция / UI + БД + интеграция |
| **Интеграции** | <внешняя система и ожидаемый ответ (успех / ошибка / таймаут)> или «—» |
| **Автоматизация** | Кандидат / Не автоматизировать (почему) / Автоматизирован: <Класс#метод> |

## Предусловия
1. <Состояние системы и данных, которое должно быть ДО шага 1. Конкретно: какая сущность, в каком статусе.>
2. <Пользователь авторизован с ролью ...>

## Шаги
| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | <одно действие пользователя> | <наблюдаемый результат: что видно на экране / какое сообщение> |
| 2 | ... | ... |

## Тестовые данные
| Поле | Значение | Комментарий |
|---|---|---|
| <Поле> | <конкретное значение> | <почему это значение: класс, граница> |

## Проверки вне UI
- БД: <что должно появиться/измениться: таблица или сущность, ключевые поля, запись в истории> или «—»
- Исходящий запрос: <в какую систему, ключевые поля> или «—»

## Постусловия
- <Что удалить/вернуть после кейса> или «—»
```

## Правила заполнения шагов
- Один шаг = одно действие. «Заполнить форму и сохранить» — два шага.
- Ожидаемый результат наблюдаем и проверяем: не «форма работает корректно», а «появилось уведомление “Пилот создан”, в таблице строка с именем и статусом “Черновик”».
- Конкретные значения вместо «ввести валидное значение»: `15`, `AT_SEG_TEST`, `Кредитная стратегия v2`.
- Тексты сообщений — дословно из требований/макетов. Нет в требованиях — пиши `<текст уточнить>` и добавь вопрос.
