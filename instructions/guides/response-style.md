# Как сделать, чтобы модель отвечала короче (или длиннее)

Для человека. Обоснования и источники — `research/10-response-style.md`.

## Где задаётся стиль
| Где работаете | Куда писать | Что уже готово |
|---|---|---|
| Qwen Code | стиль ответа: `/output-style brief` или в настройках `"general": {"outputStyle": "brief"}` | `.qwen/output-styles/brief.md`, `detailed.md`, `tech.md` |
| Любой агент (Qwen Code, OpenCode, Cursor и др.) | раздел «Как отвечать» в `AGENTS.md` | есть в `AGENTS.md` |
| Чат без агента | системный промпт / «инструкции» чата | `chat/system-prompt.md` |
| Разовый ответ | первое слово сообщения: `кратко:`, `подробно:`, `тех:` | описано в `AGENTS.md` и стилях |

Стиль Qwen Code напоминается модели **на каждом ходу**, поэтому держится в длинной сессии лучше, чем строчка в
`AGENTS.md`. Если работаете в Qwen Code — включите стиль `brief` по умолчанию, а `AGENTS.md` оставьте как запасной вариант для других агентов.

## Что работает
1. **Говорить, что делать, а не что не делать.** «Первая строка — результат; вопрос → 1–3 предложения» сильнее, чем «не пиши много».
2. **Числовые рамки.** «До 5 пунктов», «1–3 предложения», «≤2 предложения на вопрос да/нет». Слова «кратко», «лаконично» модели понимают по-разному.
3. **Шаблон ответа под тип задачи.** Правка кода → «файлы + команда проверки + итог»; метрики → «3–5 строк с числами + путь к отчёту». Модель копирует форму.
4. **Объяснить зачем.** «Ответ читают между прогонами, длинный текст прячет главное» — модель обобщает причину на похожие случаи.
5. **Стиль инструкций = стиль ответа.** Короткие инструкции без лишней разметки дают более короткие ответы; если в промпте много заголовков и жирного — их будет много и в ответе.
6. **Явное исключение для важного.** «Ошибки, риски для данных и безопасность сообщай полностью» — иначе модель начнёт резать и их.
7. **Без капса и «КРИТИЧЕСКИ ВАЖНО».** Современные модели на это перестраховываются и перегибают; обычный тон работает лучше.

## Что не работает
- `max_tokens` как способ укоротить ответ: ответ оборвётся, у рассуждающих моделей может вообще не начаться.
- Понижение `reasoning_effort` ради короткого ответа: оно уменьшает рассуждение, а не текст ответа (и ухудшает качество).
- Десятки правил стиля: каждое правило конкурирует с правилами задачи. В стиле `brief` их 8.

## Если модель всё равно многословна
1. Проверьте, что стиль действительно включён (`/output-style` в Qwen Code показывает текущий).
2. Дайте пример: «Ответ должен выглядеть так: …» — один образец действует сильнее абзаца правил.
3. Поправьте в моменте: «кратко: повтори в 3 строках» — и добавьте в стиль правило, которое было нарушено.
4. Учтите модель: в независимом тесте лишней многословности (YapBench) модели семейства GLM были среди самых «разговорчивых» на коротких вопросах, а на задачах «одна строка кода» — среди самых кратких. Для GLM шаблоны ответа особенно полезны.
