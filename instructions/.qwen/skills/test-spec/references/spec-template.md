```markdown

<Одно-два предложения: какой риск закрываем автотестами.>

- <поведение 2>

## Критерии приёмки
- AC-1. КОГДА <условие>, СИСТЕМА ДОЛЖНА <наблюдаемый результат>.
- AC-2. Дано <состояние>; Когда <действие>; Тогда <результат: UI / API / БД / исходящий запрос>.

## Тесты
| # | Тест (класс#метод) | AC | Уровень | Ловит | Кейс | Готово |

## Данные и окружение

## Изменения в каркасе
- Новые/изменённые PO, клиенты API, DAO, стабы: <список с одной строкой назначения>
```

## Пример критериев (админка стратегий)
- AC-1. КОГДА администратор сохраняет пилот с валидными данными, СИСТЕМА ДОЛЖНА показать «Пилот создан», добавить строку со статусом «Черновик», записать пилот со статусом `DRAFT` и одну запись `CREATE` в историю.
- AC-2. КОГДА процент охвата вне 1..100 или не целый, СИСТЕМА ДОЛЖНА отклонить запрос с 400 и ошибкой по полю `coveragePct`.
- AC-3. КОГДА сервис сегментов отвечает 500, СИСТЕМА ДОЛЖНА показать «Сервис сегментов недоступен», оставить форму открытой и не сохранить пилот.
