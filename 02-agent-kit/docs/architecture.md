# Архитектура фреймворка автотестов (для людей и ИИ-агента)

> Как получить первую версию: попросите агента «изучи репозиторий и заполни docs/architecture.md по этому шаблону,
> ничего не выдумывай, где не уверен — пиши `?`». Затем человек вычитывает, правит и коммитит.
> Обновлять раз в 1–2 месяца или после крупных изменений каркаса.
> Ниже — заполненный пример для эталонного кода из `03-java-examples`.

## Слои
| Слой | Пакет | Ответственность | Можно ли менять агенту |
|---|---|---|---|
| Инфраструктура | `core` | браузер, сессия, конфиг, уникальные данные, вложения, уборка | нет, только по просьбе |
| БД | `db` | пулы ro/rw, DAO разделов, record-ы строк | да: новые DAO-методы и SQL |
| Моки | `mock` | контракт `MockServer`, адаптер SberMock, стабы по интеграциям | да: стабы; адаптер — нет |
| Данные | `model` | данные форм, `valid()` + `withX()` | да |
| Страницы | `pages` | Page Object-ы и компоненты, только локаторы и действия | да |
| Шаги | `steps` | бизнес-шаги с `@Step` | да |
| Тесты | `tests/<раздел>` | сценарии и проверки | да |

## Жизненный цикл теста
1. `PlaywrightExtension.beforeEach` — новый BrowserContext с сохранённой сессией (`AuthState`), старт трассы.
2. Тест: подготовка (данные, уборка, стабы) → действия → проверки UI → БД → исходящие запросы.
3. `PlaywrightExtension.afterTestExecution` — сразу после теста: при падении скриншот и трасса в Allure.
4. `Mocks.Extension.afterEach` — при падении прикладывает журнал мока, удаляет стабы теста.
5. `Cleanup.Extension.afterEach` — выполняет уборку в обратном порядке.
6. `PlaywrightExtension.afterEach` — закрывает BrowserContext.

Порядок `@ExtendWith({PlaywrightExtension.class, Cleanup.Extension.class, Mocks.Extension.class})` важен:
расширения, объявленные позже, выполняют afterEach раньше — уборка успевает до закрытия браузера.

## Рецепты
### Новая страница
1. Снять aria-снимок страницы (см. скилл `autotest-writer`, `references/locators.md`).
2. Создать `pages/<Имя>Page.java` по образцу `PilotsPage`: конструктор с `Page`, `open()` ждёт заголовок, методы-действия и методы-локаторы.
3. Модальное окно / повторяющийся блок — отдельный класс-компонент, локаторы ищутся внутри корня.

### Новая проверка в БД
1. Таблица и колонки — из `docs/db-schema.md`.
2. SQL-файл в `src/test/resources/sql/<раздел>/`.
3. Метод в `db/<Сущность>Db.java`, record строки.

### Новая интеграция
1. Запись в `docs/integrations.md`.
2. Класс `mock/<Система>Stubs.java` с методами на каждый ответ.
